오늘 정말 고생 많으셨습니다! 가계부 프로젝트의 **4일 차**인 오늘은 단순한 로컬 웹 앱을 넘어, 실제 유저들이 가입해서 사용할 수 있는 '진정한 웹 서비스'의 틀을 갖춘 아주 의미 있는 날이었습니다.

오늘 진행된 핵심 내용들을 깔끔하게 정리해 드릴게요.

---

### 1. 예산 관리 시스템 고도화 (Supabase 연동)

- **구현 내용:** 대시보드에서 이번 달 목표 예산을 직접 수정하고 관리하는 기능을 만들었습니다.
    
- **방법:** * 예산 텍스트 클릭 시 입력창으로 변하는 **인라인 편집(In-line Edit)** UI 적용.
    
    - `localStorage`가 아닌 **Supabase `budgets` 테이블**에 저장하여 기기가 바뀌어도 데이터가 유지되도록 함.
        
    - 연도와 월별로 개별 예산을 설정할 수 있는 로직 구현.
        

### 2. "저장 후 계속 추가" 기능 (UX 개선)

- **구현 내용:** 여러 내역을 연속해서 입력할 때 모달창을 매번 닫지 않아도 되는 기능을 추가했습니다.
    
- **방법:** * `TransactionModal`에 **'저장 후 계속'** 버튼 추가.
    
    - 저장 시 `keepOpen` 플래그를 사용하여, 금액과 내용만 초기화하고 날짜와 타입(수입/지출)은 유지해 연속 입력 편의성 극대화.
        

### 3. 소셜 로그인 시스템 구축 (OAuth)

- **구현 내용:** 구글 로그인을 연동하여 개인화된 서비스의 기초를 닦았습니다.
    
- **방법:** * Supabase Auth를 사용하여 **구글 소셜 로그인** 구현.
    
    - `Login.jsx`를 문지기(Gatekeeper)로 세워 세션(`session`)이 없을 때만 로그인 창을 띄움.
        
    - `App.jsx`에서 `onAuthStateChange`를 통해 실시간 로그인 상태 감지.
        

### 4. 유저별 데이터 보안 및 분리 (RLS)

- **구현 내용:** 내가 쓴 가계부 내역을 다른 사람이 볼 수 없도록 완벽하게 차단했습니다.
    
- **방법:** * DB 테이블(`transactions`, `budgets`)에 **`user_id`** 컬럼 추가 및 기본값(`auth.uid()`) 설정.
    
    - Supabase **RLS(Row Level Security)** 정책을 `ALL` 권한으로 설정하여 `auth.uid() = user_id` 조건이 맞는 데이터만 접근 허용.
        

### 5. 트러블슈팅 및 안정화

- **내용:** 로그인 연동 시 발생하는 구글/카카오의 리다이렉트 오류와 서버 에러를 해결했습니다.
    
- **해결:** * **KOE205 & 4/0A 에러:** Redirect URI 일치 및 Client Secret 오타 수정.
    
    - **사이드바 오류:** 로그아웃 버튼 추가 과정에서의 문법 및 아이콘 Import 에러 해결.
        
    - **데이터 미표출:** RLS 정책 범위 수정(SELECT -> ALL)을 통한 CRUD 정상화.
